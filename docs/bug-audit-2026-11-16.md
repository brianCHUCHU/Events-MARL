# Pressure Plate / Navigation bug audit — 2026-11-16

This repair covers the Ours research comparison actually used in the previous
batches: Pressure Plate and Navigation, event / three fixed intervals /
single-query, with `research_metrics=True`. Existing results, checkpoints and
frozen sources are preserved. No new full experiment batch was started.

## Confirmed issues and repairs

| Issue | Repair | Effect on the completed experiments |
|---|---|---|
| Evaluation clipped the raw mean instead of using the policy's tanh transform. | Research evaluation and the four shared action builders use `tanh(mean)`. | Evaluation scores were affected. The scores did not feed optimizer updates, early stopping or checkpoint selection. The upstream shared evaluator already contained clipping; the local research evaluator inherited it. |
| PyTorch seeding/forking did not seed or restore VMAS's private, shared RNG state. | Explicit `env.reset(seed=evaluation.seed + batch)` plus exception-safe restoration of VMAS and host Torch/NumPy/Python state. Training seeds also reset an already-imported VMAS stream. | Evaluation advanced the RNG used for subsequent training resets. This changes the seeded training path; it does not establish incorrect gradients or systematic deterioration. The local integration was responsible for assuming the RNG was isolated. |
| NMD regenerated adapters with copies of one agent's LiDAR, although deployed adapters use distinct teammate inputs. | Initial/reference buffer entries retain full team LiDAR and attention masks; NMD requires those contexts and selects the recorded owner agent's adapter. | Changes Navigation training's diversity controller. The repeated-input estimator came from upstream and was inconsistent with the full-team attention context retained by the research pipeline. |
| NMD reference observations still included post-terminal padding. | Filter previous trajectory observations using the same valid-team mask used by training. | Changes Navigation's training control signal. PPO/GAE masking had been repaired earlier, but the reference estimator was still consuming padded observations. |
| No previous reference observations in round one was interpreted as a measured NMD of zero. | Do not measure/update the controller until previous observations exist; record NMD as unavailable and retain initial scale 1.0. | Changes Navigation's first training round. Missing data no longer causes an artificial controller adjustment. |
| PPO recomputed likelihoods using a hard-coded minimum standard deviation of 0.3. | Use the policy's `min_std`; research distribution traces use the same floor. | Both completed experiments used 0.3, so this did not invalidate their replay. It would break likelihood consistency when changing this parameter. |
| Return normalization ignored its valid-row mask. | Compute statistics only over valid transitions and zero invalid rows. | Both completed configs disabled return normalization. The fix protects future configurations. |
| Team minibatches could lose or split rows when dimensions did not divide; disabling minibatches still used the configured count. | Reject invalid dimensions and missing shuffle keys; use a single full batch when minibatches are disabled. | Previous batches used valid divisible dimensions with minibatches enabled. |
| Navigation's physical generator batch field counted affected teams, not actual input contexts. | Separate logical queries, input contexts, generated adapters and deployed adapters; include setup, NMD and PPO regeneration work in metrics. | Task scores and logical counts were unaffected; the old physical batch field understated work. Four refreshed agents currently cause four full-team contexts, sixteen generated adapters and four deployed adapters. |
| Pressure Plate config declared heterogeneous speeds, but the scenario ignores capabilities and hard-codes every robot to speed 1.0. | Make the four main method configs declare the actual homogeneous speeds; reject unsupported settings; save effective initial properties in `environment.json`. Navigation uses a validated configured prefix instead of substituting defaults. | Pressure Plate's actual physics is preserved. The earlier declared `[0.8, 1.0, 1.2]` was never the implemented condition. Navigation's old default substitution happened to equal its configured prefix, but other prefixes could be silently changed. |
| The older quantitative evaluator used the opposite EMA weighting convention and accumulated rewards after first termination. | Reuse training's EMA helper and mask rewards with the active episode mask. | This was not the research evaluator used for the two completed batches. Focused unit tests cover these shared-path repairs; this is not an end-to-end validation of all baseline methods. |

Non-finite research rollout outputs, rewards and PPO diagnostics now raise
instead of allowing a run to continue with a plausible-looking summary. Before
the first PPO update of each rollout, log-probability MSE must be at most 1e-6.
The logger also rejects non-finite JSON values. Configurations that the research
pipeline does not implement (mixed team sizes, discrete actions, Pressure Plate
with a drone) fail explicitly.

## What was checked beyond the known issues

- Pressure Plate's shared first-arrival bonus is paid once for each agent's
  first visit and is reset correctly for individual vector environments.
- Team termination stops later rewards, queries, GAE and PPO losses from using
  padded transitions. PPO updates are invariant to added inactive rows.
- Real models and VMAS physics, with forced asynchronous Navigation discoveries
  and Pressure Plate activation changes, replay **every** recorded action's
  log probability from the saved generation contexts. This is broader than the
  original first-minibatch diagnostic alone.
- Navigation event refreshes affect only the newly detecting agent and retain
  all teammates from its generation time. Fixed-K counts follow
  `1 + floor((episode_length - 1) / K)`; single-query counts remain one.
- Evaluation preserves training/host RNG state even when trace collection
  raises. Its initial population is independent of prior training resets.
- Different training seeds initialize different policies. Changing periodic
  evaluation frequency is checked against complete final parameter trees,
  including actor, generator, critic and saved NMD state.
- Pressure Plate's effective max speeds agree with the corrected config for
  Ours, PS, DiCo and CASH environment creation. This environment check does not
  establish correctness of those other methods' full training loops.

## Validation evidence

The focused suite passes **26 tests**, including two real-model replay tests.
The final integration matrix passes **14 cases**, covering **28 training
rounds and 40 evaluation traces**. Its maximum first-update log-probability MSE
is **1.94e-14**. For both environments, adding/removing middle evaluations
preserves final actor, generator, critic and saved NMD parameters exactly.
Different seeds initialize different policies. The new and historical summary
schemas were also checked; historical missing physical-cost fields remain
unavailable rather than receiving fabricated zero counts.

Each integration case uses two complete 200-step training rounds with two

## Interpretation and next experiment discussion

NMD still measures a **reference distribution of pre-tanh policy means**. It
uses initial full-team contexts and observations from the preceding valid
training rollout. We did not redefine target 0.007 as an observed deployment
action-distance guarantee. Changing that definition would be a method choice,
not an additional mechanical repair.

Single-query still receives fresh observations and selects new actions at
every step; only its adapters remain fixed. Good single-query performance in
Navigation is therefore not, by itself, a bug. Pressure Plate's simultaneous
team-goal condition and its reward-shaping design were not redefined to obtain
better scores. The finite 200-step episodes still use an episode-horizon value
of zero in GAE. Continuing-task bootstrapping would require a different setup.

The previously saved initial observation samples match across methods within
each training seed (1360 Navigation and 880 Pressure Plate sample comparisons,
four stored environments per batch). They change across rounds. Thus the RNG
defect was a failure of the promised fixed-population/isolation contract; it
does not prove every method received different initial conditions.

For the next discussion, prioritize a small diagnostic study before another
large seed sweep: locate Pressure Plate's loss of success using behavior and
task milestones, and compare Navigation event versus reset-only under the
corrected NMD controller. Select any cost-matched fixed interval from a
separate, explicitly labeled calibration run. Agree on environment-step budget,
evaluation population, convergence/stability measures and query-cost units
before scaling seeds. Old and new training protocols must remain separate.

The legacy non-research Ours event/token-replay path, Wind Flocking, and full
PS/DiCo/CASH training have not received this audit's end-to-end coverage. No
claim is made that the entire upstream repository is bug-free. Changes remain
local and uncommitted on `research/pressure-plate-wind-metrics`.
